# Dispatch AI — MVP Prototype

A working prototype of the AI chat/call agent platform: a landing page with a live AI chat demo, a client intake form, an AI script generator, and a review/approve dashboard.

## What's actually working right now

The landing page (`/`) has a real chat widget wired to Claude, plus a visible pricing section. The intake form (`/onboard`) saves a new client and calls Claude to draft their agent's script from the answers. The dashboard (`/dashboard`) lists every client, lets you edit the draft script, approve it, and generate a real Stripe subscription payment link to send to that client. The dashboard is protected by a login (HTTP Basic Auth), and Stripe webhooks automatically keep each client's status in sync — flipping to "paid" the moment they complete checkout, and to "cancelled" the moment their subscription actually ends, with no manual checking required either way.

Cancellation is self-service for your clients, not just you: after paying, a client lands on `/success`, which has a "Manage my subscription" button opening Stripe's own Customer Portal — from there they can cancel, update their card, or view invoices themselves, with no email or phone call to you required. You can also generate that same portal link for any paid client at any time from a button on their dashboard card, for cases where they reach out to you directly instead.

The intake form (`/onboard`) also has a small "Need help?" chat widget in the corner — a separate AI persona from the landing page demo, scoped to answering questions about the form itself, pricing, and what happens after signup, rather than pretending to be a customer's future AI agent.

Paying clients can now put a real, working AI chat widget on their *own* website, not just yours. Every paid client's dashboard card has a "Website chat widget code" box with a one-line embed snippet (`public/widget.js`, served publicly and built to run on any third-party site) -- paste it into their site and a chat bubble appears there, answering using that specific client's own founder-approved script. It's gated on `status === 'paid'` specifically, so it switches off automatically the moment a client cancels, the same way everything else here does.

Every one of those website widget conversations is now remembered, not just answered and forgotten. A paid client's dashboard card has a "Website chat conversations" section listing every conversation their widget has had, each one automatically tagged (once it's gone quiet for a few minutes) as **Booked**, **Unbooked lead**, **Question answered**, or **Not reviewed yet**, with any name/email/phone the visitor gave and a one-line summary -- plus the full transcript if you want to read it. This is step one of turning "we answer every call" into "we make sure no lead goes cold."

Step two is now built too: for any conversation tagged **Unbooked lead** where the visitor gave an email, the AI drafts a short, on-brand follow-up message (subject + body) referencing what they actually asked about. It shows up right under that conversation in the dashboard, fully editable, with "Save edits" and "Approve draft" buttons -- the same review-before-anything-goes-live pattern used for the main agent script.

Step three closes the loop: once a draft is approved, a "Send now" button appears and actually emails it to the visitor, via Resend (`lib/emailClient.js`, plain `fetch`, no SDK). Approving and sending are deliberately two separate, founder-triggered clicks -- signing off on the wording doesn't automatically put an email in a real person's inbox. Until `RESEND_API_KEY` and `FOLLOWUP_FROM_EMAIL` are set (see `LAUNCH_CHECKLIST.md` Step 9), "Send now" shows a demo-mode message instead of sending anything, the same fallback pattern used for Claude and Stripe elsewhere in this app.

Everything runs as a single Node.js process with **zero npm dependencies** — no `npm install` step is required to run it, only Node.js itself (version 18 or newer).

Without an `ANTHROPIC_API_KEY` set, the app runs in "demo mode": every AI response is a canned placeholder, but the entire flow (forms, saving, dashboard, editing, approving) is fully testable. Without a `STRIPE_SECRET_KEY` set, the payment link buttons show a demo-mode message instead of a real link. Both fallbacks, plus the dashboard login and the webhook signature verification, were tested end-to-end before this file was handed to you.

## Running it locally

1. Install Node.js 18+ if you don't have it (nodejs.org).
2. Open a terminal in this folder.
3. Copy `.env.example` to `.env` and fill in `ANTHROPIC_API_KEY` (get one at console.anthropic.com) to get real AI responses instead of placeholders.
4. Run `node server.js`.
5. Open `http://localhost:3000` in a browser.

## What's NOT built yet (by design, for an MVP)

There's no real database (client data, and now conversation data, live in JSON files — fine for testing and your first several dozen clients, not for large-scale simultaneous edits). Important: on Render, those files only survive restarts/redeploys once you've completed Step 8 in `LAUNCH_CHECKLIST.md` (a paid plan plus a persistent disk) — without it, Render's free tier silently wipes client and conversation data on every restart, which is a real risk once you have actual customers, not just a testing inconvenience.

The "never let a lead go cold" follow-up idea is now fully built end to end for new leads: every website widget conversation gets stored and tagged, unbooked leads with an email get an AI-drafted follow-up you can edit and approve, and approved drafts can actually be emailed with one more click, once Resend is connected (Step 9 in `LAUNCH_CHECKLIST.md`). What's still NOT built: reaching out to *past* customers for repeat/seasonal work (a separate feature -- it needs each client to hand over an existing customer list, which nothing here collects yet), and there's no automatic retry or delivery-failure handling if a send fails partway -- it's a single attempt, and a real error message shows if it doesn't go through. The dashboard login uses a single shared username/password rather than per-user accounts — fine for one founder, not for a team. Clients don't have their own login either — the self-service subscription portal works via a link (from their post-payment page, or generated by you on demand), not a persistent account they can log back into whenever they want. There's no live phone number yet — `scripts/create-retell-agent.js` is a ready-to-run helper for connecting an approved script to Retell AI once you have a Retell account, but it's a manual step, not automatic yet. A cancelled subscription correctly flips a client's status to "cancelled" in the dashboard, but it doesn't yet automatically pause anything in Retell — once a client has a real phone number connected, cancellation still needs a manual step to actually take their agent offline (a good next addition once Retell is wired up for real). Note that the self-service portal itself requires a one-time toggle in Stripe's own dashboard (see LAUNCH_CHECKLIST.md Step 6) — without it, the "Manage my subscription" button will show an error instead of opening the portal. The website widget code exists and works, but there's no written, step-by-step "how to add this to your website" guide for clients yet (instructions differ by platform -- WordPress, Squarespace, Wix, a custom site, etc.) -- worth writing before you rely on clients figuring out the embed snippet entirely on their own.

## File guide

`server.js` is the entire backend — routes, static file serving, dashboard auth, Stripe checkout and webhook handling, all in one file for easy reading. `lib/claude.js` calls the Anthropic API (and falls back to placeholder text if no key is set). `lib/stripeClient.js` creates Stripe Checkout sessions and verifies webhook signatures, using plain `fetch` and Node's built-in `crypto` (no Stripe SDK dependency). `lib/scriptPrompt.js` builds the prompt that turns intake answers into a draft script — this is the actual "product" logic worth iterating on as you learn what makes a good script. `lib/helpChatPrompt.js` is the system prompt for the small help-chat widget on the intake form. `lib/widgetChatPrompt.js` builds a paying client's own AI persona from their approved script, for their website widget. `lib/conversationInsightPrompt.js` builds the prompt (and parses the response) used to tag a finished website widget conversation as booked, an unbooked lead, a resolved question, or unclear. `lib/followUpPrompt.js` builds the prompt (and parses the response) used to draft a follow-up email for an unbooked lead, in that client's own tone. `lib/emailClient.js` sends the actual follow-up email via Resend's API, using plain `fetch` (no SDK), once a draft is approved. `lib/db.js` is the JSON-file storage, for both clients and widget conversations. `public/` has the site's pages (landing, onboard, dashboard, success) as plain HTML/CSS/JS — no framework, no build step. `public/widget.js` is the embeddable chat widget clients paste into their own websites -- it's plain, dependency-free JavaScript on purpose, since it has to run safely on someone else's site alongside whatever else is already there. `scripts/create-retell-agent.js` pushes an approved script live to Retell AI (run manually, not from the dashboard).

See `LAUNCH_CHECKLIST.md` for the non-technical, step-by-step path from this code to a real URL real customers can use.
